Theory Notes — Monitoring, Auditing and Notifications in AWS

So far you have built things in AWS — users, servers, storage, networks. This module is about watching them. Once a system is running, four questions come up again and again:

Question Service What it gives you
Is my server healthy right now?CloudWatchMetrics, logs and alarms
Who deleted my server?CloudTrailA record of every action taken
How do I get told immediately?SNSEmail / SMS notifications
Am I wasting money or leaving a security hole?Trusted AdvisorAn automatic account check-up

1. The Big Picture

Analogy — your car

Your AWS account is a car.

CloudWatch is the dashboard — the speedometer, the fuel gauge, the engine temperature light. It tells you how the car is running right now.

CloudTrail is the logbook at the gate — it records who took the car out, at what time, and where they went.

SNS is the buzzer — when the fuel gets low, something has to actually beep at you.

Trusted Advisor is the service centre — once in a while a mechanic checks everything and hands you a report.

These four services work as two separate chains. Learn them as two chains and the whole module becomes easy:

The one line to remember CloudWatch tells you WHAT is happening. CloudTrail tells you WHO did it. Almost every exam question on this module is testing whether you know this difference.

2. Amazon CloudWatch

Analogy — the dashboard

When you sit in a car you never open the bonnet to check the engine. You look at the dashboard. Speed, fuel, temperature — all the important numbers in one place, updating continuously.

CloudWatch is that dashboard for your AWS resources.

CloudWatch does three things. Learn them in this order:

  1. Metrics — collects numbers over time (CPU usage, network traffic)
  2. Logs — collects text output from applications
  3. Alarms — reacts automatically when a number crosses a line you set

2.1 Metrics — how a metric is identified

Every metric in CloudWatch has the same four parts. Once you can read this shape, you can find any metric in the console:

Namespace AWS/EC2 ← which service sent it Metric name CPUUtilization ← what is being measured Dimension InstanceId = i-0abc123 ← which exact resource Period 5 minutes ← one reading every 5 min

How often CloudWatch takes a reading depends on which monitoring you choose:

Type Reading every Cost Notes
Basic monitoring 5 minutes Free This is the default on every EC2 instance
Detailed monitoring 1 minute Paid Enable it per instance when you need faster reaction

2.2 Logs

CloudWatch Logs stores text in three levels:

Log Group  →  Log Stream  →  Log Events

A Log Group is one application or one log file, for example /var/log/httpd. A Log Stream is one source inside that group — normally one server. Log Events are the individual lines of text.

2.3 Alarms — the three states

Analogy — a fever thermometer

You decide the line: anything above 100°F is a fever.

Reading is 98.4 → normal. Reading is 102 → fever, do something. Thermometer battery is dead and shows nothing → you cannot tell.

A CloudWatch alarm has exactly those three states.

OKThe metric is inside the threshold. Nothing to do.
ALARMThe threshold was crossed. Actions fire now.
INSUFFICIENT_DATANot enough readings to decide yet.

2.4 Important — CloudWatch cannot see memory by default

Remember this An EC2 instance sends CPU, network and disk I/O to CloudWatch automatically. It does not send memory (RAM) usage or free disk space. For those you must install the CloudWatch Agent inside the operating system.
Analogy — a house from the street

Stand outside a house. You can see the electricity meter spinning and the water meter running — so you know roughly how busy the house is. You can count people going in and out.

But you cannot see how full the fridge is. That is inside. Somebody inside the house has to come to the window and tell you.

That somebody is the CloudWatch Agent.

3. AWS CloudTrail

Analogy — the register at the society gate

Every visitor who enters your building writes in the register at the gate: name, flat number, time in, time out. Nobody is stopped — the register simply records what happened.

A month later, if something goes missing, you open the register and find out who came that day.

CloudTrail is that register for your AWS account.

The idea behind CloudTrail Every action in AWS is an API call. Clicking a button in the console, running an AWS CLI command, or calling the SDK from code — all three become the same API call underneath. CloudTrail records those calls.

Each recorded event answers five questions:

QuestionFieldExample
Who?User identitystudent-sahil
What?Event nameTerminateInstances
When?Event time29 Oct 2026, 14:32:08 UTC
From where?Source IP address49.36.182.7
On what?Resourcei-0abc123def456

3.1 Three facts you must remember

FactDetail
Event History is already on CloudTrail records management events by default, free, and keeps the last 90 days. You do not have to switch anything on.
Need more than 90 days? Create a Trail. It delivers the log files into an S3 bucket, where they can be kept as long as you like.
Data events are off by default Management events (launched a server, created a bucket) are recorded. Data events (read one S3 object, invoked a Lambda) are not — there would be millions of them and it costs extra.

4. Amazon SNS — Simple Notification Service

Analogy — the class WhatsApp group

A teacher has to inform 60 parents that tomorrow is a holiday. She does not message each parent one by one. She posts one message in the group and all 60 receive it.

The group is the SNS Topic. The parents are the Subscribers. Sending one message that reaches everybody is called fan-out.

And just like a group, a parent must join before they receive anything.

You will hit this in the lab After you add an email subscription, AWS sends a confirmation email. Until you open it and click Confirm subscription, the status stays “Pending confirmation” and no notifications will arrive at all. Check your spam folder too.

SNS vs SQS — in one line

SNS pushes the message out to subscribers the moment it arrives. SQS holds messages in a queue and the application pulls them when it is ready. Push versus pull.

5. AWS Trusted Advisor

Analogy — car servicing

Once a year you take the car to the service centre. The mechanic checks the engine, brakes, tyres, oil and AC, then hands you a report: “brakes fine, tyres worn, replace oil.”

Trusted Advisor does that for your AWS account, automatically, across five areas.

Category Example of what it finds
Cost OptimizationAn EC2 instance running all month with almost no CPU usage — you are paying for nothing
PerformanceAn instance running at full load that needs a bigger size
SecurityA security group open to 0.0.0.0/0, or MFA missing on the root account
Fault ToleranceNo EBS snapshots taken, or everything placed in a single Availability Zone
Service LimitsYou have used 80% of the VPCs allowed in this region
Note for the lab On a free or Basic support plan only a limited set of checks is available. The rest appear locked and need a paid Business or Enterprise support plan. This is normal — do not think your account is broken.
